# Graph Sync -- Full Vault Navigation Rebuild

Full re-render of the vault's navigation layer plus a frontmatter drift check.

The graph is **derived from metadata**: `Graph/index.md` and the MOCs are generated by
`scripts/graph-render.py` from frontmatter and the concept index
(`_generated/vault-hygiene/vault-index.json`, when present). There is **no inline wiki-link
pass** (that convention existed for graph viewers and is retired); links are written only
as structural edges (`superseded_by`, a `## Related` line to a hub, entity-registry rows), always
path-qualified.

**When to use:** first-time setup, after a restructure (folder moves, client archive or rename),
after a bulk import, or when `Graph/` looks stale. The daily sync runs the renderer each day, so
this is rarely needed.

**Runtime:** seconds for the render; longer only if the frontmatter drift check finds work.

---

## How the Graph Works

1. **Frontmatter** -- YAML metadata at the top of every file (`type`, `status`, `client`, tags).
   This is the input the renderer reads.
2. **Structural edges** -- a small number of deliberate links: `superseded_by` in frontmatter, a
   `## Related` line to a hub on a doc that needs one, and entity-registry rows. Not inline
   mentions.
3. **Entity registry** (`Graph/entity-registry.md`) -- maps terms to their page, for lookups.
4. **Rendered navigation** (`Graph/index.md` + MOCs) -- generated by the renderer, not by hand.

---

## Section 1: Frontmatter Audit

Process every markdown file (the renderer already excludes `.claude/`, `Graph/`, `Templates/`,
`_generated/`, `scripts/`). For each file, add frontmatter if missing or complete
it without overwriting existing values.

**Type from path** (reuse an existing `type` value before inventing one):
- `**/Company Profile.md` -> `client-profile`
- `**/Transcripts/**` -> `transcript`
- `Resources/People/**` -> `person`
- `Resources/Concepts/**` -> `concept`
- `Resources/Reference/**` -> `reference`
- `**/SOPs/**` -> `sop`
- `Projects/**` -> `project`
- `Work/Daily/**` -> `daily`
- `Inbox/**` -> `inbox`
- `Archive/**` -> keep the real type, set `status: archived`
- default -> `reference`

**Client from path:** `Work/Clients/<Name>/` -> the folder name with any emoji stripped; your
internal/company folder -> that folder's name.

Required minimum is `type` + `created`. Add `summary` or `aliases` by hand only where a reader
benefits (a hub doc, an entity page with nicknames).

Report: `Frontmatter: N files changed`

---

## Section 2: Structural Edges

Only for docs with no path to a hub. Triage, do not auto-action everything.

1. Find core docs with no path to a hub. A `link` edge to just any page does not count; the
   target must be a hub (a Company Profile, a concept page, or an SOP). Use the renderer's export:
   `python3 scripts/graph-render.py --json /tmp/graph.json --dry-run`, then for each node find its
   outgoing `link` edges and check whether any target is a `client-profile`, `concept`, or `sop`
   node (join against the `nodes` array by `type`). Nodes with no such hub link, and no `## Related`
   section in the file, are the ones that need one (a short Python snippet over the export is fine).
2. Client and sales docs under `Work/Clients/<X>/` get one `## Related` line to their hub,
   path-qualified. Resources and internal notes: leave unless an obvious hub exists. Records
   (transcripts, daily notes) are never edited.
3. New entity pages (`Resources/People/`, `Resources/Concepts/`) get a row in
   `Graph/entity-registry.md`.

Report: `Edges: N Related sections added, N registry rows added`

---

## Section 3: Render

```bash
python3 scripts/graph-render.py --json _generated/vault-hygiene/graph.json
```

Rewrites `Graph/index.md` and the generated block of each MOC (`Clients.md`, `People.md`,
`Projects.md`, `Concepts.md`, `SOPs.md`) only when the generated body changed. The renderer owns
everything between the `<!-- graph-render:begin -->` and `<!-- graph-render:end -->` markers;
any hand-written intro above `begin` survives. A private top-level folder (default `Personal/`)
never appears in `Graph/`; override with `graph_private_top:` in the vault schema YAML, and name
your internal/company folder with `graph_company_folder:`.

Report the renderer's one-line summary.

---

## Section 4: Stats

From the renderer's summary and the JSON export (nodes with type, client, concept, entities;
edges of kind `link`, `superseded_by`, `entity:<name>`, `semantic`):

- Core docs, index entries, and per-MOC counts
- Edges by kind
- Top 10 nodes by degree (from the export)
- Client folders without a Company Profile (the renderer lists them at the bottom of
  `Graph/Clients.md`)
